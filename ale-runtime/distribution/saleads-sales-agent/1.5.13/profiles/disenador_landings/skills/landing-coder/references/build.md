Implement page.json and design.json faithfully in index.html and styles.css. Keep one clear closing action.
Use mobile-first layout, responsive clamp/grid, coherent spacing/type/color variables and CSS composition.
The first viewport must communicate the actual promise and action without hiding headline/CTA in animation.
Price/proof appear only when genuinely available. Preserve the chosen direction rather than falling back
to a generic centered hero and repeated equal cards just to make implementation easy.

Marketing is visible: emphasize a few meaningful pain/desire words, make real objections readable,
show supported mechanism/process/inclusions, and place actual proof near the appropriate CTA.
Service pages can use process diagrams, timelines or typographic composition with real information.
Do not fabricate chats, seals, before/after results or customer scenes as factual proof.

Use exact platform markup in platform.md. Motion uses supported data-sa-* attributes and CSS transitions;
no arbitrary JS. With reduced motion or no JS, all content remains visible and usable.
Use accessible contrast, heading structure, focus and 44px touch targets; no horizontal overflow at 360/390px.
Reserve image geometry, lazy-load below the fold and keep meaningful alt text. Do not inline binary images.
Keep both files within SaleADS limits. Preserve data-edit IDs and the sa-fonts block when revising.
Do not print the whole code in customer chat: write it to the task artifact paths.
